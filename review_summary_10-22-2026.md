## 1. Documentation review

### High priority

1. Stale series counts. `README.md` (lines 5 and 130), `docs/architecture.md` (line 34), and `docs/development.md` (line 31) say 25 FRED series. The repo actually contains 30 CSVs in `data/raw/`, and `series.py` defines 32 `SeriesSpec` entries. Reconcile the count and clarify whether “25” means FRED-only, catalog entries, or something else.
2. `bls_data.py` is missing from module inventories. It is omitted from:
    - `docs/README.md` line 24 (“the five Python modules”)
    - `AGENTS.md` architecture table (lines 40–44)
    - `docs/architecture.md` Modules section
    - `docs/development.md` Repository layout
    - Root `README.md` does include it (line 110). Add it consistently.
3. Broken link. `docs/data.md` → Sources contains `[bls_data.py](bls_data.py)`, which resolves to `docs/bls_data.py` (not found). It should be `../bls_data.py`.

### Medium priority

1. BLS cache path mismatch. `README.md` project layout says BLS cache goes to `data/raw/bls/` (line 115), but `bls_data.py` sets `CACHE_DIR = data/raw` (line 24), and the two BLS JSON files are in `data/raw/`. Either move the cache or update the docs. Moving it would also make `clear_bls_cache()` safer.
2. Hidden document. `docs/roadmap-original-notes.md` is not linked from the `docs/README.md` map or the root `README.md` documentation table. Add an “Archive” entry or move it to `docs/archive/`.
3. Malformed Markdown. The BLS_API_KEY tip in `README.md` (lines 65–67) has unmatched backticks, e.g. `$env:BLS_API_KEY="your_key_here"` and `On Linux:export...`. Fix formatting.
4. Platform inconsistency. `pixi.toml` declares `platforms = ["win-64"]` only (line 4), while the README gives macOS/Linux setup tips (lines 65–67). Either add platforms or mark the project Windows-only.

### Low priority

1. No `pyproject.toml`. Configuration is split across `pixi.toml` (environment/tasks) and `pytest.ini`; ruff runs on defaults. Optional consolidation into `pyproject.toml` for tool config and package metadata.
2. README “Requirements” omits `ruff` and `pytest-cov` (both in `pixi.toml`). Minor.
3. Positive: Documentation is unusually thorough — architecture, data, methodology, outputs, development, roadmap, a docs map, a contributor pointer, and an agent brief with a defect register. The `AGENTS.md` defect register and testing philosophy are excellent.

## 2. Organization and code structure

### Strengths

- Clear domain separation: `series.py` (catalog), `fred_data.py`/`bls_data.py` (clients), `labor_data.py` (assembly), `analysis.py` (stats/report), `labor_viz.py` (visuals); `data/raw/`, `output/`, `docs/`, `tests/`.
- Tests mirror modules; 8 test files.
- Zero dead code/cycles; flat root layout is appropriate for the current size.

### Improvement candidates

1. Duplicated helpers. `_extract_year_month` and `_year_month_to_ordinal` are duplicated verbatim in `fred_data.py` (lines 228/234) and `bls_data.py` (lines 195/201). The two clients also appear to duplicate cache-staleness/HTTP/error-handling patterns. Consider a shared `data_common.py` for cache age, date parsing, and request/error helpers.
2. Large module / top hotspot. `analysis.py` is ~1,042 lines. `calculate_shift_share` is the top hotspot (cyclomatic complexity 30, churn 48.28); `_shift_share_stats` is complexity 21. Consider extracting shift-share math into its own module or reducing nesting; optionally split `analysis.py` into stats/report/CLI if it grows further.
3. `clear_bls_cache()` risk. It deletes all `*.json` in `data/raw/`, shared with FRED CSVs. Separating BLS cache into `data/raw/bls/` would prevent accidental deletion and align with the README.
4. Flat root layout. Six modules at root is acceptable now; revisit `src/` packaging only if the module count/import graph grows.
